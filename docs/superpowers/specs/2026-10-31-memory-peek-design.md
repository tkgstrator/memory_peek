# memory_peek design

[日本語版はこちら](2026-10-31-memory-peek-design.ja.md)

The user wants an Atmosphère 1.12.1 environment running strictly the necessary custom sysmodules: FTP and game-memory reading. Album must open normally, game LayeredFS and external ExeFS/IPS modifications must be disabled, and the stock sys-botbase must not run. Because the target Switch and SD card are not immediately accessible, this repository delivers a locally built, reviewable read-only memory reader; hardware installation and runtime operational claims require subsequent live SD inventorying and on-device testing.

## memory_peek boundary

- A dedicated Switch sysmodule reads the memory of the currently running application process and exposes strictly bounded read and read-only metadata operations over TCP. It provides no controller input, file write, RAM write, process freeze, or generic command execution endpoints.
- Uses TCP port 6000 after disabling stock sys-botbase so existing NXCTF read clients can connect without modifications. Retains sys-botbase-compatible command syntax and uppercase hexadecimal single-line responses: `getVersion`, `getTitleID`, `getMainNsoBase`, `getBuildID` (first 8 bytes), `getHeapBase`, `isProgramRunning`, `peekMain`, `peekAbsolute`, and `peekAbsoluteMulti`. `getVersion` returns the numeric protocol version `1.0.0`; `getIdentity` returns `memory_peek/1` to identify the module. Any unrecognized command returns an explicit error response.
- Accepts at most 32 ranges and 1 MiB total per request, matching the NXCTF client limit. The complete read operation must succeed before any payload bytes are transmitted. Line length is capped at 2,048 bytes with an idle timeout. Only one client connection is serviced at a time.
- Uses provisional Program ID `0x43004D5045454B01` and halts deployment if the target SD card already contains this ID. This ID is distinct from stock sys-botbase; final collision verification serves as a mandatory deployment gate.
- Reads application memory through Atmosphère 1.12.1's `dmnt:cht` metadata and memory-read IPC only when `dmnt` has already attached to the process at application launch. The reader must never attach a debugger, call `ForceOpenCheatProcess`, or invoke pause, resume, write, freeze, or cheat-toggle IPC methods. If `dmnt` is not attached, it returns an unavailable error (`ERR READER_UNAVAILABLE`) without interfering with the running game. For a designated title/build, an empty cheat file prompts `dmnt` to attach prior to game execution; it contains no opcodes and must be verified on hardware. Memory reading must never pause or stop a running game.
- Grants only the necessary services and local-process syscalls required by the socket adapter. Excludes all direct target-process debug, write, and process-control syscalls from the NPDM. Because `dmnt:cht` itself provides write interfaces to callers, this read-only boundary is enforced by source code and compiled binary constraints, rather than kernel capability restrictions on the IPC service itself. Artifact auditing must reject unrecognized kernel capability categories, extra service grants, and any write/pause/freeze call references.
- The command parser must reject unrecognized commands, malformed numbers, oversized lines, out-of-range reads, and integer overflows cleanly without side effects. Read failures return explicit error lines and never emit partial payloads presented as success.
- Explicitly maintains source provenance and licensing. sys-botbase source is not copied without GPL-3.0 attribution. TCP port 6000 exposes application memory to other clients on the local network; no confidentiality or authentication guarantees are claimed.

## SD integration boundary

- Keeps official Atmosphère ZIP archives and fusee binaries intact as verified baseline inputs. Overwriting archives in place without cleanup leaves obsolete `contents` and `exefs_patches` active.
- Following live inventorying, backs up all existing SD card files, retains only confirmed FTP and memory_peek custom sysmodules under active `atmosphere/contents`, and moves external game overrides and `exefs_patches` outside active directories. A narrowly scoped, empty per-title/build cheat file may be staged to prompt `dmnt`'s pre-launch handle; this file is not a LayeredFS or ExeFS override and contains no opcodes.
- Configures explicit `override_config.ini` entries to disable Album and application HBL hijacking. Maintains a direct SD recovery path because an FTP failure post-reboot would preclude remote rollback.
- Validates archive checksums, staged SD layout, successful boot, Album accessibility, FTP service, and a live memory read from the intended game. File verification alone does not substitute for runtime hardware activation.
