# memory_peek 設計仕様

[English](2026-10-31-memory-peek-design.md)

ユーザーは、必要最低限の FTP およびゲームメモリ読み取り用のカスタム sysmodule のみが動作する Atmosphère 1.12.1 環境を求めています。アルバム機能は通常通り起動でき、ゲームの LayeredFS および外部の ExeFS/IPS パッチは無効化され、標準の sys-botbase は動作させてはなりません。対象の Switch 実機および SD カードは現時点で直接操作できないため、本リポジトリではまず、ローカルでビルドおよびレビューが可能な読み取り専用メモリリーダーを提供します。実機へのインストールやランタイム動作の主張は、その後の実機 SD カードのインベントリ確認およびデバイス検証を経て行われます。

## memory_peek の境界（Boundary）

- 専用の Switch sysmodule が、現在実行中のアプリケーションプロセスのメモリを読み取り、厳格に制限された読み取りおよび読み取り専用メタデータ操作のみを TCP 経由で公開します。コントローラー入力、ファイル書き込み、RAM 書き込み、プロセスのフリーズ、汎用コマンド実行などの操作は一切提供しません。
- 標準の sys-botbase を無効化した後、既存の NXCTF 読み取りクライアントがそのまま接続できるように TCP ポート 6000 を使用します。sys-botbase 互換のコマンド体系および大文字 16 進数の 1 行応答フォーマットを維持します: `getVersion`、`getTitleID`、`getMainNsoBase`、`getBuildID`（先頭 8 バイト）、`getHeapBase`、`isProgramRunning`、`peekMain`、`peekAbsolute`、`peekAbsoluteMulti`。`getVersion` は数値プロトコルバージョン `1.0.0` を返し、`getIdentity` は実際のモジュールを識別するために `memory_peek/1` を返します。これら以外の未知のコマンドにはエラー行を返します。
- 1 回のリクエストで受け付ける範囲は最大 32 個、合計 1 MiB までとし、NXCTF クライアントの制限に合わせます。データ行が送信される前に、要求されたすべての読み取りが完全に成功している必要があります。1 行の長さは最大 2,048 バイトに制限され、アイドルタイムアウトが適用されます。同時に処理するクライアント接続は 1 つのみです。
- 仮の Program ID として `0x43004D5045454B01` を使用し、対象 SD カードで既に使われている場合はデプロイを中止します。この ID は標準の sys-botbase とは異なります。最終的な衝突確認はデプロイメントゲートの 1 つです。
- アプリケーション起動時に `dmnt` が既にプロセスにアタッチしている場合にのみ、Atmosphère 1.12.1 の `dmnt:cht` メタデータおよびメモリ読み取り IPC を介して読み取りを行います。リーダー側からデバッガをアタッチしたり、`ForceOpenCheatProcess` を呼び出したり、一時停止（pause）、再開（resume）、書き込み（write）、フリーズ（freeze）、チート切り替え（cheat-toggle）の IPC メソッドを呼び出したりしてはなりません。`dmnt` がアタッチされていない場合は、実行中のゲームに影響を与えることなく利用不可エラー（`ERR READER_UNAVAILABLE`）を返します。対象のタイトル/ビルドに対しては、空のチートファイルを配置することでゲーム開始前に `dmnt` をアタッチさせることができます。このファイルには opcode は含まれず、実機での検証が必要です。メモリ読み取りによって実行中のゲームを停止させてはなりません。
- アダプターが必要とするサービスおよびローカルプロセスのシステムコール（SVC）のみを許可します。対象プロセスに対する直接のデバッグ、書き込み、プロセス制御システムコールはすべて NPDM から除外します。`dmnt:cht` 自体は呼び出し元に対して書き込み用インターフェースも公開しているため、この「読み取り専用」という境界は IPC サービス側のカーネル権限による制限ではなく、ソースコードおよびコンパイル済みバイナリの制約によって保証されます。成果物の監査では、未承認のカーネル機能カテゴリ、追加サービス、および write/pause/freeze 呼び出しの参照を拒否しなければなりません。
- コマンドプロトコルパーサーは、未知のコマンド、不正な形式の数値、サイズ超過の行、範囲外の読み取り、および整数のオーバーフローを副作用なく拒否しなければなりません。読み取りが失敗した場合は明確なエラーを返し、部分的なデータを成功として返してはなりません。
- ソースコードの出典とライセンスを明示します。GPL-3.0 の帰属表示なしに sys-botbase のソースコードをコピーしてはなりません。TCP ポート 6000 は同一 LAN 上の他のクライアントにゲームメモリを公開するため、秘匿性や認証を主張してはなりません。

## SD カード統合の境界（SD integration boundary）

- 公式の Atmosphère ZIP アーカイブおよび fusee バイナリは、検証済み入力として変更を加えずに維持します。ZIP ファイルを単に上書き展開するだけでは、古い `contents` や `exefs_patches` が有効なまま残ってしまいます。
- 実機のインベントリ確認後、既存の SD カードファイルをバックアップし、稼働中の `atmosphere/contents` 以下には確認済みの FTP および memory_peek カスタム sysmodule のみを残し、外部のゲーム MOD や `exefs_patches` は有効なパスの外部へ移動します。対象のタイトル/ビルドに対して `dmnt` の起動前ハンドルを確立するために、必要に応じてスコープを絞った空のチートファイルを配置します。これは LayeredFS や ExeFS の MOD ではなく、opcode も含みません。
- 明示的な `override_config.ini` 設定を使用して、アルバムおよびアプリケーションの HBL 乗っ取りを無効化します。再起動後に FTP が失敗した場合に備え、直接 SD カードを復元できるリカバリ手段を常に確保しておきます。
- アーカイブのハッシュ値、生成された SD カード構成、実機での起動、アルバム機能、FTP、および対象ゲームからの実際のメモリ読み取りを検証します。ファイルの読み戻し確認だけでは、実機ランタイムでの有効化を証明したことにはなりません。
