# memory_peek 実装計画

[English](2026-10-31-memory-peek.md)

> **エージェント向け指示:** 必須サブスキル: 本計画をタスク単位で進めるために superpowers:subagent-driven-development（推奨）または superpowers:executing-plans を使用してください。進捗追跡にはチェックボックス（`- [ ]`）構文を使用します。

**目標:** 専用の読み取り専用ゲームメモリ sysmodule をビルドし、対象実機が利用可能になった時点で安全にロールバック可能な Atmosphère 1.12.1 SD 構成を準備する。

**アーキテクチャ:** TCP ポート 6000 で待機する軽量な Switch 向け C 言語 sysmodule。設計仕様で定義された読み取り要求のみを受け付け、NXCTF 読み取りクライアントの応答フォーマットに準拠します。プロトコル解析は純粋な C 言語で実装されホスト上でテストされます。ソケット結合テストでは、ゲーム開始前に `dmnt` がアタッチ済みの場合にのみ Atmosphère の `dmnt:cht` メタデータおよびメモリ読み取り IPC を使用します。メモリ読み取り処理が実行中のゲームにアタッチしたり一時停止したりすることは一切ありません。SD カードのステージングは別個の作業フェーズであり、実機のインベントリ確認および対象ゲームのビルド ID 確認が必要です。

**技術スタック:** C 言語、libnx、devkitA64 Docker イメージ、Python 検証スイート、Atmosphère 1.12.1。

**仕様書:** `docs/superpowers/specs/2026-10-31-memory-peek-design.ja.md`

## グローバルな制約事項

- RAM 書き込み、コントローラー入力、プロセスのフリーズ、ファイルシステム変更、汎用コマンド実行のエンドポイントを一切公開しないこと。
- リクエスト行を最大 2,048 バイト、最大 32 範囲、合計 1 MiB に制限し、整数オーバーフローを防御すること。未知のコマンドは明示的に拒否すること。
- 仮の Program ID `0x43004D5045454B01`、`getVersion=1.0.0`、`getIdentity=memory_peek/1` を使用すること。仕様書で定義された NXCTF 読み取りコマンドおよび応答形式に準拠すること。
- 公式の Atmosphère 1.12.1 ダウンロードファイルを変更せず維持し、公開されている SHA-256 チェックサムを検証すること。
- SD カードへのファイル配置をもって実機ランタイムでの動作成功とみなさないこと。実機の識別情報およびリカバリ手順をデプロイ前に確立すること。

## レビュー時の着眼点

- `poke` や `freeze` 要求に対して明示的な拒否応答を返し、メモリの読み書きを一切行わないこと。
- サイズ超過や不正な形式のリクエスト行によってパーサーバッファがオーバーフローしないこと。
- アドレス加算の算術オーバーフローや最大値を超える読み取り要求が、`dmnt:cht` IPC 呼び出しを行う前に安全にエラーとなること。
- 読み取り失敗時に、部分的なバイト列を成功応答として返さないこと。
- ビルドされた NPDM から対象プロセスに対する直接のデバッグ/書き込み権限が除外され、必要なサービスとローカル SVC のみが許可されていること。また、ソースコードおよびバイナリ内に write、pause、freeze、controller 関連 API の参照が存在しないこと。`dmnt:cht` は幅広い IPC サービスであるため、実際に呼び出されるメソッドを監査し、その信頼境界を明確に記録すること。

### タスク 2: Switch 読み取りアダプターとパッケージング

**対象ファイル:** `source/main.c`, `source/memory.c`, `source/memory.h`, `memory_peek.json`, ビルド用 `Makefile`, `README.md`, `LICENSE` の作成。

**インターフェース:** 単一の TCP サービスがタスク 1 のプロトコルを受け付け、現在起動中のアプリケーションメタデータおよび制限されたメモリ範囲を読み取り、リクエストごとに 1 つの完全な応答を返します。

- [x] 未承認の NPDM カーネル機能、対象プロセスへの直接のデバッグ/書き込み/プロセス制御システムコール、予期しないサービス付与、または write、pause、freeze、controller メソッドへのソース/バイナリ参照を拒否するビルド成果物チェックを追加。監査済み NPDM が NSP 内に含まれていることを証明。
- [x] 意図的に安全でないフィクスチャでチェックが失敗することを確認した上で、最小限のモジュールおよび NPDM がチェックに合格することを確認。
- [x] ピン留めされたローカルキャッシュの devkitPro イメージダイジェスト `sha256:1fc388c3a0d34bd2045a6dadcb1020e069d5f876a187fd705de14b4440c00282` を使用して NSP をビルド。生成された NPDM/ELF を検査し、ホストおよびソケットテストを再実行。`dmnt` ハンドルが存在しない場合の読み取りが、アタッチや一時停止呼び出しを行うことなく利用不可エラーを返すことを確認。実機でのランタイム成功を主張する前に、実機上での起動前アタッチおよび継続的なメモリ読み取りを確認。
